# راهنمای سادهٔ پرینتوپیا 🖨️

این راهنما برای کسی است که **تا حالا سایت راه‌اندازی نکرده**. همه‌چیز به زبان سادهٔ فارسی توضیح داده شده.

---

## ۱) این سایت چگونه کار می‌کند؟

```
GitHub  ←  کدِ سایت اینجا نگه‌داری می‌شود
   ↓ (خودکار)
Cloudflare  ←  سایت را می‌سازد و روی اینترنت منتشر می‌کند
   ↓
/admin/setup  ←  اولین‌بار اینجا رمز مدیر را تعیین می‌کنید
   ↓
/admin  ←  از این به بعد، مدیریت از همین پنل انجام می‌شود
```

مدیریت سایت از یک پنل مخفی به‌نام `/admin` انجام می‌شود.

---

## ۲) شروع سریع در چند دقیقه

1. کد را در GitHub بگذارید و Cloudflare را به آن مخزن وصل کنید (یک‌بار).
2. وقتی سایت منتشر شد، یک **پایگاه‌دادهٔ D1** بسازید و آن را متصل کنید (تنها کارِ دستی؛ پایین توضیح داده شده).
3. آدرس `https://YOUR-DOMAIN/admin/setup` را باز کنید.
4. یک **رمز عبور** برای مدیر انتخاب کنید و دکمه را بزنید.
5. تمام! وارد پنل مدیریت شوید.

✅ شما **هیچ هش یا کلیدی را دستی نمی‌سازید**. سیستم خودش همه‌چیز را امن انجام می‌دهد.

---

## ۳) قبل از شروع

- [ ] یک حساب **GitHub** و مخزنِ کدِ سایت.
- [ ] یک حساب **Cloudflare** که سایت از GitHub منتشر می‌شود.
- [ ] ساخت یک پایگاه‌دادهٔ **D1** (یک‌بار؛ در ادامه).
- [ ] (اختیاری) دامنهٔ شخصی.

🚨 این‌ها را **هرگز** به اشتراک نگذارید: رمز مدیر، کلید، توکن، فایل `.env`.

---

## ۴) تنها کار دستی: ساخت و اتصال پایگاه‌داده D1

برای ذخیرهٔ امنِ حسابِ مدیر، سایت به یک پایگاه‌دادهٔ کوچک نیاز دارد. این کار **یک‌بار** انجام می‌شود و **رمز یا کلیدی در کار نیست**.

1. در داشبورد Cloudflare به **Workers & Pages → D1** بروید و **Create database** را بزنید (مثلاً با نام `printopia`).
2. **Database ID** ساخته‌شده را کپی کنید.
3. در مخزن GitHub فایل `wrangler.jsonc` را باز کنید؛ بخشِ یادداشت‌شدهٔ `d1_databases` را از حالت یادداشت خارج کنید و شناسه را جای‌گذاری کنید:

   ```
   "d1_databases": [
     { "binding": "DB", "database_name": "printopia", "database_id": "شناسهٔ شما" }
   ]
   ```
4. تغییر را ذخیره (commit) کنید تا Cloudflare دوباره سایت را بسازد.

> این تنها قدمِ دستی است. پس از آن، همه‌چیز از داخل پنل انجام می‌شود.

---

## ۵) راه‌اندازی خودکار با Setup Wizard

آدرس:
```
https://YOUR-DOMAIN/admin/setup
```

این «ویزارد» وضعیت را بررسی می‌کند:

- **وضعیت استقرار سایت**
- **وضعیت پایگاه‌داده** (آیا D1 متصل است؟)
- **وضعیت حساب مدیر** (آیا ساخته شده؟)
- **وضعیت راه‌اندازی**

سپس:
1. اگر D1 متصل نباشد → همان راهنمای بالا را نشان می‌دهد.
2. اگر راه‌اندازی کامل باشد → پیام «راه‌اندازی قبلاً کامل شده» و دکمهٔ ورود.
3. اگر راه‌اندازی ناقص باشد → دکمهٔ **«شروع راه‌اندازی»**.

در مرحلهٔ ساخت حساب مدیر:
- «رمز عبور» و «تکرار رمز عبور» را بنویسید.
- یک نوارِ قدرتِ رمز می‌بینید (رمز را نشان نمی‌دهد).
- دکمهٔ **«ساخت حساب مدیر و پایان راه‌اندازی»** را بزنید.

در پایان:
- «راه‌اندازی اولیه انجام شد»
- «حساب مدیر ساخته شد»
- دکمهٔ **«ورود به پنل»**.

اگر وسط کار قطع شد: دوباره `/admin/setup` را باز کنید؛ چیزی خراب نمی‌شود و setup از نو روی حسابِ موجود انجام نمی‌گیرد.

اگر `/admin/setup` بعد از راه‌اندازی باز شود: پیام «راه‌اندازی قبلاً کامل شده» را می‌بینید و فقط ورود پیشنهاد می‌شود.

---

## ۶) ساخت کلید Cloudflare (آیا لازم است؟)

❌ **خیر.** هیچ «Global API Key» یا توکنی لازم نیست.
رمزِ مدیر و کلیدِ امن، **داخلِ پایگاه‌داده و توسط خودِ سایت** ساخته و نگه‌داری می‌شوند. شما فقط یک پایگاه‌داده D1 می‌سازید (که راز نیست).

---

## ۷) ورود به پنل مدیریت

- آدرس: `https://YOUR-DOMAIN/admin`
- رمز عبور را وارد کنید و «ورود» را بزنید.
- خروج: از منو «خروج از حساب».

اگر ورود شکست خورد:
- اگر پیام «راه‌اندازی کامل نشده» را دیدید → به `/admin/setup` بروید.
- اگر «رمز نادرست» → رمز را بررسی کنید.
- اگر «تلاش‌های زیادی» → چند دقیقه صبر کنید.

---

## ۸) کار با پنل مدیریت

از منوی کناری می‌توانید: مقاله‌ها، محصولات، دسته‌بندی‌ها، صفحات، رسانه‌ها، منوها، ظاهر، سئو، ریدایرکت‌ها و تنظیمات را مدیریت کنید.

مقاله‌ها:
- **ذخیره پیش‌نویس**، **پیش‌نمایش**، **انتشار**، **لغو انتشار/بایگانی**، و **حذف** (با تأیید).

عکس‌ها:
- ابتدا **متن جایگزین فارسی (Alt)** را بنویسید (الزامی).
- فرمت: WebP، AVIF، JPG، PNG — حداکثر ۳ مگابایت.

> نکتهٔ صادقانه: در این نسخه، محتوای ویرایش‌شده (مقاله/محصول/تنظیمات) در **مرورگر شما** ذخیره می‌شود. حسابِ مدیر و ورودِ امن در D1 نگه‌داری می‌شوند.

---

## ۹) GitHub و Cloudflare چه زمانی لازم‌اند؟

- **کدِ سایت**: از GitHub منتشر می‌شود؛ هر تغییرِ کد → انتشارِ جدید در Cloudflare.
- **محتوا**: از داخل پنل مدیریت انجام می‌شود.
- بررسی وضعیت انتشار: داشبورد Cloudflare → پروژه → **Deployments** (🟢 موفق / 🟡 در حال ساخت / 🔴 ناموفق).

---

## ۱۰) چه چیزهایی دیگر لازم نیست دستی انجام بدهم؟

✅ ساخت `ADMIN_PASSWORD_HASH` — **لازم نیست** (سیستم خودش می‌سازد).
✅ ساخت `SESSION_SECRET` — **لازم نیست** (سیستم خودش می‌سازد).
✅ باز کردن Variables/Secrets در Cloudflare برای این دو مورد — **لازم نیست**.
✅ توکنِ GitHub یا کلید خصوصی — **لازم نیست**.
✅ Global API Key — **هرگز** استفاده نشود.

تنها کار دستی: **ساخت و اتصالِ پایگاه‌دادهٔ D1** (یک‌بار).

---

## ۱۱) رفع خطاهای رایج

| مشکل | راه‌حل ساده |
|---|---|
| `/admin/setup` باز نمی‌شود | بررسی کنید deploy موفق بوده؛ کد جدید منتشر شده باشد |
| پیام «پایگاه‌داده متصل نیست» | D1 را بسازید و `database_id` را در `wrangler.jsonc` بگذارید و commit کنید |
| پیام «بخش سرور فعال نیست» | کدِ جدید (شامل Worker) هنوز منتشر نشده؛ دوباره deploy کنید |
| ساخت حساب مدیر ناموفق بود | رمز حداقل ۸ نویسه و تکرار یکسان باشد؛ دوباره تلاش کنید |
| ورود کار نکرد | اگر setup کامل نیست → `/admin/setup`؛ وگرنه رمز را بررسی کنید |
| `/admin` صفحهٔ اصلی را باز کرد | deploy را بررسی کنید و صفحه را سخت بازخوانی کنید |

---

## ۱۲) نکات امنیتی بسیار مهم

- 🚨 رمز مدیر، کلیدها، توکن‌ها و فایل `.env` را **هرگز** به اشتراک نگذارید یا در GitHub نگذارید.
- اگر رازی افشا شد، فوراً آن را باطل/جایگزین کنید.
- رمزِ مدیر فقط در سرور و به‌صورت هش نگه‌داری می‌شود؛ نسخهٔ خوانا هرگز ذخیره نمی‌شود.
- نشستِ ورود در یک کوکی امن (HttpOnly) قرار دارد که مرورگر نمی‌تواند آن را بخواند.

---

## ۱۳) واژه‌نامه ساده

- **Worker**: برنامه‌ای روی Cloudflare که سایت را اجرا و درخواست‌ها را مدیریت می‌کند.
- **D1**: پایگاه‌دادهٔ سادهٔ Cloudflare که داده‌ها در آن ذخیره می‌شوند.
- **Deploy / انتشار**: قابل‌دیدن‌کردن سایت روی اینترنت.
- **پنل مدیریت (/admin)**: صفحه‌ای که فقط شما سایت را از آن اداره می‌کنید.
- **هاش (Hash)**: نسخهٔ رمزشدهٔ رمز که سیستم خودش می‌سازد.
- **GitHub repository (مخزن)**: پوشهٔ آنلاینِ کدِ سایت.

---
