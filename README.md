# راهنمای سادهٔ پرینتوپیا 🖨️

این راهنما برای کسی است که **تا حالا سایت راه‌اندازی نکرده**. همه‌چیز به زبان سادهٔ فارسی توضیح داده شده.

---

## ۱) شروع سریع

1. کد سایت را در **GitHub** بگذارید و **Cloudflare** را به همان مخزن وصل کنید.
2. صبر کنید تا اولین انتشار (deploy) با موفقیت انجام شود.
3. آدرس زیر را باز کنید:
   ```
   https://YOUR-DOMAIN/admin/setup
   ```
4. مراحل راهنما را کامل کنید (توضیح پایین).

---

## ۲) پایگاه‌داده چگونه وصل می‌شود؟

پایگاه‌داده (D1) محل نگهداریِ اطلاعاتِ پنل است: حسابِ مدیر، رمزِ هش‌شده و تنظیمات امن.

> **نکتهٔ بسیار مهم:** چون سایت شما از GitHub منتشر می‌شود، فایل `wrangler.jsonc` **تنها مرجع درست** برای اتصال‌هاست. اگر پایگاه‌داده را فقط در **داشبوردِ Cloudflare** وصل کنید، در انتشارِ بعدی **از بین می‌رود** و سایت دوباره می‌گوید «پایگاه‌داده متصل نیست».

بنابراین اتصالِ پایگاه‌داده را **یک‌بار و فقط در `wrangler.jsonc`** ثبت می‌کنیم:

1. در داشبورد Cloudflare: **Workers & Pages → D1** → پایگاه‌دادهٔ `printopia` را باز کنید.
2. مقدار **Database ID** (یک شناسهٔ طولانی) را کپی کنید.
3. در مخزن GitHub فایل `wrangler.jsonc` را ویرایش کنید؛ بخشِ یادداشت‌شدهٔ `d1_databases` را از حالت یادداشت خارج کنید و شناسهٔ واقعی را در `database_id` بگذارید.
4. تغییر را ذخیره (commit) کنید تا Cloudflare دوباره سایت را بسازد.

```
"d1_databases": [
  { "binding": "DB", "database_name": "printopia", "database_id": "شناسهٔ واقعی شما" }
]
```

> این تنها کارِ دستی است و **راز/رمز نیست**؛ فقط یک شناسه است.

---

## ۳) اگر Setup گفت «پایگاه‌داده متصل نیست»

این پیام یعنی اتصالِ پایگاه‌داده به **نسخهٔ فعالِ سایت** ثبت نشده. سه حالت متفاوت وجود دارد که باید بدانید:

| حالت | معنی | راه‌حل |
|---|---|---|
| پایگاه‌داده **ساخته** شده | ولی هنوز به سایت وصل نیست | اتصال را در `wrangler.jsonc` ثبت کنید (بخش ۲) |
| پایگاه‌داده **وصل** شده | ولی در نسخهٔ فعال نیست | حتماً `commit` کرده‌اید تا انتشار جدید انجام شود؟ |
| پایگاه‌داده وصل است ولی **جدول‌ها نیستند** | آماده‌سازی اولیه لازم است | نیازی به کار دستی نیست؛ خود سایت جدول‌ها را می‌سازد |

- اگر در صفحهٔ `/admin/setup` این پیام را دیدید، دکمهٔ **«بررسی دوباره»** را بزنید تا سایت وضعیت را دوباره چک کند.
- جدول‌های لازم (حساب مدیر و تنظیمات) به‌صورت **خودکار و ایمن** ساخته می‌شوند؛ شما نباید SQL اجرا کنید.

---

## ۴) ساخت حساب مدیر

وقتی پایگاه‌داده وصل شد، `/admin/setup` به مرحلهٔ ساخت حساب مدیر می‌رود:

- فقط **رمز عبور** و **تکرار آن** را بنویسید.
- یک نوارِ قدرتِ رمز می‌بینید (رمز را نشان نمی‌دهد).
- دکمهٔ پایان راه‌اندازی را بزنید.

سیستم خودش رمز را به‌صورت امن (هش) ذخیره می‌کند.

> ✅ **لازم نیست هش رمز یا SESSION_SECRET بسازید یا در Cloudflare وارد کنید.**
> هیچ متغیر محیطی برای راه‌اندازی لازم نیست.

---

## ۵) ورود و خروج

- آدرس پنل: `https://YOUR-DOMAIN/admin`
- رمز را وارد کنید و «ورود» را بزنید.
- خروج: از منو «خروج از حساب».

نشستِ ورود در یک کوکی امن (HttpOnly) نگه‌داری می‌شود که مرورگر نمی‌تواند آن را بخواند.

---

## ۶) رفع خطاهای رایج

| مشکل | معنی / راه‌حل |
|---|---|
| `/admin/setup` می‌گوید «پایگاه‌داده متصل نیست» | اتصال را در `wrangler.jsonc` ثبت و commit کنید؛ سپس «بررسی دوباره» |
| خطای **۱۰۰۲۱** هنگام انتشار | `database_id` واقعی نیست؛ شناسهٔ درست را از داشبورد D1 کپی کنید |
| اتصال در داشبورد اضافه شد ولی باز هم می‌گوید وصل نیست | اتصالِ داشبوردی در انتشار GitHub نگه‌داری نمی‌شود؛ حتماً در `wrangler.jsonc` باشد |
| پایگاه‌داده در حسابِ Cloudflare دیگری است | پایگاه‌داده و Worker باید در **یک حساب** باشند |
| پایگاه‌داده پیدا شد ولی «پاسخ‌گو نیست» | معمولاً موقتی است؛ «بررسی دوباره» را بزنید |
| جدول‌ها ناقص‌اند | خود سایت جدول‌ها را به‌صورت ایمن می‌سازد؛ نیازی به کار دستی نیست |
| ورود ناموفق بود | اگر راه‌اندازی کامل نیست → `/admin/setup`؛ وگرنه رمز را بررسی کنید |
| «راه‌اندازی قبلاً کامل شده» | یعنی حسابِ مدیر وجود دارد؛ به `/admin/login` بروید |
| `/admin` صفحهٔ اصلی را باز کرد | انتشار را بررسی کنید و صفحه را سخت بازخوانی کنید |

---

## ۷) امنیت

- 🚨 رمز مدیر، توکن‌ها، شناسه‌ها و فایل `.env` را **هرگز** به اشتراک نگذارید یا در GitHub به‌صورت راز نگذارید.
- شناسهٔ `database_id` راز نیست، ولی آن را هم بی‌دلیل منتشر نکنید.
- رمزِ مدیر فقط در سرور و به‌صورت **هش** ذخیره می‌شود؛ نسخهٔ خوانا هرگز ذخیره نمی‌شود.
- اگر رازی افشا شد، فوراً آن را باطل/جایگزین کنید.

---

## ۸) واژه‌نامه ساده

- **Worker**: برنامهٔ روی Cloudflare که سایت را اجرا می‌کند.
- **D1**: پایگاه‌دادهٔ سادهٔ Cloudflare.
- **wrangler.jsonc**: فایلِ پیکربندیِ سایت؛ **مرجع درست** برای اتصال‌ها.
- **Database ID**: شناسهٔ یکتای پایگاه‌داده (نه راز).
- **deploy / انتشار**: قابل‌دیدن‌کردنِ سایت روی اینترنت.
- **هاش (Hash)**: نسخهٔ رمزشدهٔ رمز که سایت خودش می‌سازد.

---

## خلاصهٔ نهایی

- تنها کار دستی: **ثبت اتصالِ D1 در `wrangler.jsonc` با شناسهٔ واقعی** (یک‌بار).
- آدرس راه‌اندازی: `https://YOUR-DOMAIN/admin/setup`
- اولین کار در ویزارد: **انتخابِ رمزِ مدیر**.
- نیازی به ساختِ `ADMIN_PASSWORD_HASH` یا `SESSION_SECRET` نیست.
