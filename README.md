# راهنمای سادهٔ پرینتوپیا 🖨️

## جریان محتوا (چگونه کار می‌کند)

```
پنل مدیریت (/admin)
   ↓ نوشتن یا ویرایش مقاله
پایگاه‌داده D1 (منبعِ واقعیِ داده‌ها)
   ↓ خواندن مقاله‌های منتشرشده
سایت عمومی (/blog)
```

- مقاله‌ای که در پنل **منتشر** می‌کنید، در `/blog` سایت نمایش داده می‌شود.
- مقاله‌ای که **حذف** یا **لغو انتشار** می‌کنید، از سایت برداشته می‌شود.
- این تغییرها از طریق **پایگاه‌دادهٔ مرکزی (D1)** انجام می‌شوند و برای همهٔ بازدیدکنندگان قابل‌مشاهده هستند.

---

## شروع سریع

1. کد را در GitHub بگذارید و Cloudflare را وصل کنید.
2. یک پایگاه‌دادهٔ **D1** بسازید و آن را با شناسهٔ واقعی در `wrangler.jsonc` ثبت کنید.
3. `https://YOUR-DOMAIN/admin/setup` را باز کنید و رمز مدیر را تعیین کنید.
4. وارد پنل شوید و مقاله بسازید.

---

## پایگاه‌داده چگونه وصل می‌شود؟

چون سایت از GitHub منتشر می‌شود، `wrangler.jsonc` مرجع درست است. اتصالی که فقط در داشبورد اضافه کنید، در انتشار بعدی از بین می‌رود.

1. داشبورد Cloudflare → **Workers & Pages → D1** → پایگاه‌دادهٔ `printopia` → کپی **Database ID**.
2. در GitHub فایل `wrangler.jsonc` را ویرایش: بخش `d1_databases` را از حالت یادداشت خارج کنید و شناسه را بگذارید.
3. ذخیره (commit) کنید تا Cloudflare دوباره بسازد.

```
"d1_databases": [
  { "binding": "DB", "database_name": "printopia", "database_id": "شناسهٔ واقعی" }
]
```

---

## ساخت حساب مدیر

- به `/admin/setup` بروید.
- یک رمز عبور انتخاب کنید.
- سیستم خودش رمز را امن ذخیره می‌کند؛ **لازم نیست هش یا SESSION_SECRET بسازید**.

---

## کار با پنل مدیریت

### مقاله‌ها
1. از منو **«پست‌ها و مقالات»** → **«مقاله جدید»**.
2. عنوان، اسلاگ، خلاصه، دسته‌بندی و متن را بنویسید (با بلوک‌ها).
3. **«ذخیره پیش‌نویس»** → بدون نمایش در سایت.
4. **«انتشار»** → در سایت نمایش داده می‌شود.
5. ویرایش: روی «ویرایش» بزنید، تغییر دهید، دوباره «انتشار».
6. حذف: روی سطل زباله → تأیید. پست از سایت برداشته می‌شود.

> مقاله‌ها در D1 ذخیره می‌شوند و برای همهٔ بازدیدکنندگان قابل‌مشاهده هستند.

### عکس‌ها
- در بخش «رسانه‌ها» آپلود کنید (با متن جایگزین فارسی).
- در ویرایشگر مقاله از «از رسانه‌ها» انتخاب کنید.

### سایر بخش‌ها
محصولات، صفحات، منوها، ظاهر، سئو و تنظیمات: قابل ویرایش هستند. (محصولات در نسخهٔ فعلی از داده‌های بسته‌بندی‌شدهٔ پروژه استفاده می‌کنند.)

---

## رفع خطاهای رایج

| مشکل | راه‌حل |
|---|---|
| **پست در پنل ذخیره می‌شود ولی در سایت دیده نمی‌شود** | وضعیت پست را روی «منتشرشده» بگذارید (نه پیش‌نویس) |
| **پست حذف شده ولی هنوز در سایت دیده می‌شود** | تا ۳۰ ثانیه کش مرورگر/CDN ممکن است قدیمی باشد؛ صفحه را بازخوانی کنید |
| **تغییرات با تأخیر نمایش داده می‌شوند** | کش عمومی ۳۰ ثانیه است؛ صبر کنید یا بازخوانی کنید |
| **سایت کند شده است** | کد جدید منتشر شده باشد؟ Worker فقط برای `/api/*` فعال است |
| `/admin/setup` می‌گوید پایگاه‌داده وصل نیست | شناسهٔ D1 را در `wrangler.jsonc` ثبت و commit کنید |
| خطای **۱۰۰۲۱** | شناسهٔ واقعی D1 را بگذارید (نه مقدار ساختگی) |
| ورود ناموفق بود | اگر راه‌اندازی کامل نیست → `/admin/setup`؛ وگرنه رمز را بررسی کنید |

## امنیت

- 🚨 رمز مدیر، توکن‌ها و فایل `.env` را هرگز به اشتراک نگذارید.
- رمزِ مدیر فقط در سرور و به‌صورت هش ذخیره می‌شود.
- نشست ورود در کوکی امن (HttpOnly) است.
- محتوای عمومی (مقاله‌های منتشرشده) با کش ۳۰ ثانیه‌ای ارائه می‌شود؛ داده‌های ادمین هرگز کش نمی‌شوند.

---

## چه چیزهایی هنوز استاتیک است؟

- محصولات و دسته‌بندی‌های محصولات: از داده‌های بسته‌بندی‌شدهٔ پروژه (می‌توان از پنل ویرایش کرد ولی ذخیره‌سازی در مرورگر است).
- محتوای صفحهٔ اصلی (هیرو، متن‌ها): از کد پروژه.
- مقاله‌ها و وبلاگ: **کاملاً پویا و در D1** (ویرایش از پنل → نمایش فوری در سایت).

---

## خلاصه

- محتوای ویرایشی (مقاله‌ها): **D1 → سایت** (کاملاً همگام).
- محتوای استاتیک (محصولات، صفحهٔ اصلی): از کد پروژه.
- تنها کار دستی: ثبت اتصال D1 در `wrangler.jsonc` (یک‌بار).
- آدرس پنل: `https://YOUR-DOMAIN/admin`
